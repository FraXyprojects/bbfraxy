## 2024-05-18 - Client-Side Markdown Link Parser Protocol Whitelist
**Vulnerability:** Markdown parsing using RegEx `replace` without protocol verification allows client-side XSS via `[text](javascript:alert(1))` payloads. Also lacked quotation mark escaping allowing for attribute breakout attacks.
**Learning:** Vanilla JS implementations of markdown parsers that rely on chained regex `.replace()` are highly vulnerable unless strict protocol whitelisting and HTML entity escaping are enforced before URL injection.
**Prevention:** Always use an allowlist approach for URL protocols (e.g. `^https?:|^mailto:|^\/`) and verify quotation marks are escaped when crafting HTML tags manually via string manipulation.
## 2024-05-24 - Path Traversal (SSRF) in GitHub API Proxy Worker
**Vulnerability:** The `handleRepoFile` function in `workers/github-simplifier/src/index.js` lacked validation against path traversal payloads (`..`). When an attacker supplied a path containing `..`, the path was decoded, split, mapped, encoded, and joined again, ultimately resulting in a path like `../../..` being passed directly to `https://api.github.com/repos/owner/repo/contents/...`. This allowed escaping the `/repos/owner/repo/contents/` context on the GitHub API, acting as an SSRF / Path Traversal vulnerability that could be used to query arbitrary endpoints using the worker's GitHub token.
**Learning:** Even when path segments are correctly URI encoded individually using `.map(encodeURIComponent).join("/")`, dot-dot (`..`) relative pathing logic is typically evaluated *after* parsing the path in upstream servers or fetch implementations. Therefore, `..` remains functional for path traversal against external APIs if not explicitly disallowed.
**Prevention:** Explicitly deny the sequence `..` (or `path.includes("..")`) in all user-supplied file paths that will be used to construct requests to upstream APIs.

## 2024-05-25 - Fix Path Traversal Bypass and URIError DoS
**Vulnerability:** Double/recursive URL encoding (e.g., `%252e%252e`) bypasses strict `..` path checks in Cloudflare Worker endpoints, leading to path traversal. Additionally, malformed `%` encoding causes unhandled `URIError`, crashing the worker.
**Learning:** URL path segment validation for traversal MUST recursively decode the input until stable before literal checks, while still passing the original string downstream to preserve valid encoded entities. Additionally, `decodeURIComponent` MUST always be wrapped in `try/catch` in Cloudflare Workers to prevent denial of service from malformed inputs.
**Prevention:** Use a recursive decoding validation loop with a depth limit and string normalization, and ensure all external input decoding uses `try/catch` structures.
